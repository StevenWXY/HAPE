## 本轮修复

- 修复后台创建空投和写入执行结果表单双重 `JSON.stringify`，保证两个表单发送 JSON 对象。
- 钱包页长交易哈希在移动端可换行，375px 页面不再横向溢出。
- 普通操作的同一 `requestId` 若更换资产、数量、时长、网络或确认状态，统一返回 `request_id_reused`，避免幂等键重放成另一笔操作。
- 空投失败状态改为终态；回执写回要求 66 字节 BNB 交易哈希，失败必须提供原因；代币必须匹配规则。
- 自适应发行器增加 `epochAllocated`，同一期不能通过多个提案突破 25 bps；年度归属按真实 365 天边界计算。
- 后台不再把管理员/执行器密钥写入 `sessionStorage`，仅保存在当前页面内存；语言偏好仍可保存。

## 已知阻塞和风险

1. **真实海文发写操作不再重复执行。** 早前已获授权的测试消耗过一枚真实资产（数量由 3 变为 2），重试幂等；本轮只读取精确模板余额，返回 `2`，没有继续核销、转赠或提现。海文发 H5 只读会话可见账户和背包（背包显示全部资产 2,992 项），该总数不应与单模板余额混用。
2. **外部核销与 Clipli 权益未自动闭环。** 海文发适配器成功后只记录 `ExternalAssetRedemption`，不会凭外部 `tplId` 自动生成 Clipli HAPW 核销、CLIP 或空投；在没有经过审核的资产映射和计价规则前，不能擅自补发。
3. **真实合约和 DEX 尚未上线。** Hardhat 部署只在隔离 Chain ID 97 完成；输出地址是临时账户地址，不能用于真实交易。生产 DEX 应使用已审计的 PancakeSwap BNB 部署，不应直接使用本地最小 AMM。
4. **经济储备是有限的。** 900,000,000 创世供应、1,000,000,000 硬顶意味着最多 100,000,000 自适应发行储备。按年度 5% 上限，极端持续增长约两年多会耗尽储备；硬顶能保护总量，但不能保证激励永续。
5. **开发工具链存在上游漏洞告警。** 完整 `npm audit` 报告 45 项（17 high），集中在 Hardhat、solc、Mocha、覆盖率和传递依赖；`npm audit fix --force` 会升级 Hardhat 3 并产生破坏性变更，未自动执行。生产运行时不加载该工具链，但 CI 应隔离并安排升级验证。
6. **应用层仍需上线加固。** CSP 当前含 `unsafe-inline`；普通状态接口仍是匿名演示会话，不可直接暴露到公网；生产需要数据库事务/唯一索引、用户会话或签名授权、速率限制、审计日志脱敏、Merkle 快照签名、链上确认数和执行器多签。
7. **工具覆盖有限。** 当前环境没有 Slither、Mythril、Echidna、Foundry、Semgrep 等工具，因此合约安全结论是测试加人工审查，不等同第三方审计或形式化证明。

## 外部动作边界

Clipli 的海文发应用密钥只保存在本地环境变量中，没有写入前端或仓库。本轮在明确授权后完成了一次真实只读模板余额查询；之后未继续发送外部请求。真实 BNB 部署、空投、DEX 授权和兑换必须另行确认并使用受资助的测试账户、多签或硬件钱包。
