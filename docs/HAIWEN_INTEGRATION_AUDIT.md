# 海文发接口与资产闭环核对

核对日期：2026-09-08。依据：`api/openapi_external_platform.md`。资产集成已在本地测试，未执行不可逆核销或链上转账。短信排查情况见下文。

## 上游接口覆盖

| 海文发接口 | Clipli 对应实现 | 核对结果 |
| --- | --- | --- |
| `GET /openapi/works` | `/api/v1/integrations/platform/works`；作品页 | 完整分页，保留图片、作者、权利人、作品分类、介绍及发行统计 |
| `GET /openapi/tpls` | `/api/v1/integrations/platform/templates`；海文发资产目录 | 完整分页、按 workId 筛选，保留原始元数据；模板与规则映射分离 |
| `GET /openapi/user/bind/status` | 绑定详情、计数、迁移预览和执行前复核 | 撤销、缺失或外部 ID 不匹配时停止资产操作 |
| `POST /openapi/user/bind/sms` | verification-codes | 服务端认证，短信由海文发发送；本地挑战不冒充上游短信有效期 |
| `POST /openapi/user/bind` | bindings | 校验 bound、externalUserId 和 boundAt，保留一对一绑定与请求幂等 |
| `GET /openapi/user/assets/count` | users/{userId}/asset-counts | 每批最多 100 个模板；按实际分页模板查询；缺失、负数和重复数量拒绝展示为真实余额 |
| `POST /openapi/asset/write-off` | 运营审核后调用 migrations | 真实绑定、数量、规则和金库预检；原 requestNo 重试；校验完整 SUCCESS 回执后一次性入账 |

所有上游请求携带 `x-app-id/x-app-key`，HTTP 200 中的非零业务 code 仍按错误处理。缺少成功 envelope 或 data 不当成成功。前端不接触上游凭据。

海文发测试环境的实际只读核对：15 个作品、34 个版权模板，两页模板分别 20 和 14 项；15 个作品和 22 个模板带图片，已验证实际图片可渲染。其余模板没有上游图片，页面使用缺图状态，不补造素材。目录逐页汇总与上游 total 一致，ID 不重复。

## 兑换与空投

1. 用户绑定海文发，查看每种模板当前可兑换数量。
2. 选择 1 至 100 份，预览授权、创作额度、CLIP 和收款钱包，勾选不可逆核销条款后提交审核。
3. 运营后台审核原申请。服务端复核绑定和原规则条件，核销前预留金库资金；海文发确认后创建有来源凭据的 HAPW，并完成一次核销奖励。
4. 已连接钱包的奖励进入空投队列，CLIP 被预留，不能同时站内消费。尚未连接钱包时先留在站内，之后可申请领取。尚未提交链上的空投可取消并释放预留。
5. 独立执行器使用已部署的 CLIP ERC-20 合约转账。签名交易先持久化，重试复用原始交易和 nonce。API 验证主网、代币、金库、收款方、金额和至少 3 次确认后才标记成功。空投失败退款与取消均幂等。

管理员直接迁移 API 继续保留权限保护；浏览器不携带运营密钥发起普通用户兑换。运营页中的密钥仅用于显式授权的运营操作。

批量迁移使用独立 ID，避免同一时间的多份资产共用奖励编号。记账失败整体回滚；迁移、申请与账本写入本地持久文件。进程重启恢复原记录，中断的审核进入待处理状态，可按原申请重试。文件仓储只支持单进程，排他锁阻止同一账本被多个进程同时结算。

## 文档未提供的能力

- 计数接口只返回当前可核销数量，不是全部持仓。挂单、冻结、锁定、失效及历史已核销资产无法通过这七项接口枚举。
- 没有单件资产 ID、NFT tokenId、链上合约、用户资产明细、划转撤销或核销回执查询接口。Clipli 不能为这些字段伪造上游凭证，也不能声称覆盖海文发全部历史资产。
- 核销请求成功但响应丢失时，依赖相同 requestNo 的上游幂等重试；回执矛盾进入人工对账。需要海文发提供查询接口，才能进一步自动化对账。
- OpenSea 等其他平台仍未完成账户与资产接入，页面保持未开放状态。

## 正式运行前提

目前已有配置指向 `https://api-test.hnccc.com/api`。测试数据可浏览，不能兑换为真实 Clipli 资产。未找到正式海文发凭据、已配置 CLIP 主网合约及有余额的金库，未开展真实核销或真实空投验收。

服务端需要：`CLIPLI_EXTERNAL_PLATFORM_URL=https://api.hnccc.com/api`、`CLIPLI_EXTERNAL_PLATFORM_APP_ID`、`CLIPLI_EXTERNAL_PLATFORM_APP_KEY`、`CLIPLI_EXTERNAL_ASSET_MAPPINGS`、`CLIPLI_ADMIN_API_KEY`、`CLIPLI_AIRDROP_EXECUTOR_KEY`、`CLIPLI_BNB_RPC_URL`、`CLIPLI_CLIP_CONTRACT`、`CLIPLI_TREASURY_ADDRESS` 和持久化 `CLIPLI_STATE_FILE`。映射中的额度及价格须由运营确认，不能按发行量推算。

真实 CLIP 按 BNB 主网、18 位精度和至少 3 次确认处理。启动时从链上读取金库余额并减去未结算义务，不写入假金库余额。金库不足时拒绝核销。执行器额外使用 `CLIPLI_EXECUTOR_PRIVATE_KEY`，该值仅供独立进程使用，不应注入 Web 服务进程。

运营人员审核后，可执行单笔任务：

```bash
node scripts/execute-airdrop.js <airdrop-id>
```

执行器中断后须保存 `.data/airdrop-executor`，包括原始签名交易；确认没有其他执行器运行后才能移除遗留的 `executor.lock` 并恢复。不得删除原交易记录后用新 nonce 重发。链上交易待确认时重复运行同一任务进行恢复。

当前应用仍使用单账户本地会话，钱包连接只登记地址，缺少多用户鉴权和钱包控制权签名证明。上述实现可用于本地集成及受控单账户操作，不等于已可直接上线处理公众真实资产。公开部署前必须实现按用户隔离的登录、授权、账本与钱包签名验证。
